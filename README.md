## 这是什么

不是 Aspen 教程，而是一份**可执行的作战记录**。它回答三个问题：

1. **AI 怎么在没有 GUI 的情况下操作 Aspen？** → COM 自动化 + `.bkp` 文件级手术
2. **AI 怎么保证自己算的数是对的？** → 报告解析 + 逐项核对 + 对照实验
3. **这套打法在真实项目里跑通过吗？** → 跑通过，案例见 [`05-案例-烟酰胺10000ta/`](./05-案例-烟酰胺10000ta/)

## 这不是什么

- ❌ 不是 Aspen Plus 的入门教程
- ❌ 不包含任何商业软件的安装包或许可
- ❌ 不包含上游工具包的源码（见下方[依赖的上游项目](#依赖的上游项目)）

### `04-脚本库/` 按前缀定位用途

| 前缀 | 含义 | 典型用途 |
|---|---|---|
| `dump_*` | 导出/探查 | 把 bkp 段、COM 字段树、模块参数导出成文本 |
| `chk_*` / `check_*` | 校验 | 核对参数是否落库、物料是否平衡 |
| `cmp_*` | 对比 | 两个 bkp / 两组结果的逐项差异 |
| `diag_*` | 诊断 | 针对某个异常做定向排查 |
| `test_*` | 受控实验 | 一次只改一个变量，验证某个假设 |
| `fix_*` / `apply_*` | 施加变更 | 把确定的修改写回模型 |
| `parse_*` | 解析 | 解析 Aspen 报告文本/TSV 为结构化数据 |
| `probe_*` / `explore_*` | 探路 | 不确定 API/字段时的试探脚本 |

## 十秒版方法论

| 场景 | 正确做法 | 常见错法 |
|---|---|---|
| 改模块参数 | COM 直接写 → 重跑 → 核读 | 改完不核对（静默失效） |
| 改 COM 触达不到的设置 | `.bkp` 文本替换 + **校验替换计数** | 直接 `replace`，返 0 也不报错 |
| 组分表 / 亨利组分 | **只能走 GUI** | 脚本硬写（Aspen 崩溃或文件损坏） |
| 反应热计算 | 先审量纲：`kmol/h × kJ/mol = MJ/h` | 把 MJ/h 当 kW，再 ×3.6（放大 3.6 倍） |
| 警告处理 | 分类：初始化旁路 / 相态 / 物性荒谬 | 一概屏蔽 |
| 数字核对 | 以导出报告为唯一权威源 | 用旧模型数据或手算值 |

### 改模型的四条路径（优先级从高到低）

1. **COM 直接写** —— 最快，但只能改「文档化字段」
2. **`.bkp` 文本替换** —— 能改 COM 触达不到的段
3. **示例文件对照** —— 拿 Aspen 自带示例找到正确写法再照抄
4. **GUI** —— 最后手段（组分表、亨利组分必须走界面）

> ⚠️ 实测：`FREE_WATER` / 亨利组分用 COM 直写**会令 Aspen 崩溃**；文本注入要么被忽略、要么损坏文件。**二者必须经 GUI。**

## 案例：烟酰胺 10000 t/a

工艺路线：3-甲基吡啶气相氨氧化 → 吸收 → 甲苯萃取 → 四塔精馏 → 化学水解 → 中和 → 脱色 → 三效蒸发 → 结晶 → 离心 → 干燥

| 指标 | 结果 |
|---|---|
| 模型规模 | 36 单元 / 61 流股 / 15 组分，物性方法 NRTL |
| 模型状态 | Terminal / Severe / Errors **全为 0** |
| 总物料平衡 | 进 15006.04 kg/h = 出 15006.04 kg/h，偏差 **0.0000%** |
| 产品产量 | 1411.6 kg/h ≈ **10163.8 t/a**，纯度 99.62 wt% |
| 反应器净移热 | **2.19 MW**（熔盐产 1.0 MPa 蒸汽 3.9 t/h） |

> 本案例最有价值的部分不是模型本身，而是
> [`数据核对与订正说明.md`](./05-案例-烟酰胺10000ta/数据核对与订正说明.md) ——
> 它记录了**用 Aspen 计算报告反向核对设计文档、并订正了多处实质性错误**的全过程。
> 其中一处「反应热单位错误导致放热量放大 3.6 倍」，连带污染了熔盐量、产汽量和蒸汽平衡结论。

## 环境要求

| 项 | 版本 / 说明 |
|---|---|
| Aspen Plus | **V15**（需 COM / Automation 可用，需合法授权） |
| Python（COM 脚本） | 需装 `pywin32`，例如 `D:\<化工运行时>\python-env` |
| Python（表格文档） | 需装 `openpyxl`、`python-docx`，例如 `Python 3.10+` |
| 平台 | Windows（Aspen COM 仅 Windows） |

> **关于脚本里的路径**：本仓库的脚本中所有本机绝对路径**已替换为占位符**
> （如 `D:\<化工工作区>`、`C:\Users\<用户名>`、`D:\<Python3.10>`）。
> 直接运行前请按你的实际环境替换。这也是为什么脚本**不能开箱即用**——
> 它们记录的是**方法**，不是打包好的产品。
