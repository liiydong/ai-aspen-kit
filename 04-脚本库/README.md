# 脚本库说明

本目录收录了「AI 做 Aspen」全过程中实际写过的 **383 个 Python 脚本**，是**方法的物证** ——
每个脚本都对应一次真实的排查、尝试或验证。

> ## 📖 先看 [INDEX.md](./INDEX.md)
>
> **这个目录最有价值的部分是索引，不是脚本本身。**
>
> 383 个脚本不是 383 个工具，而是**一条时间线**：模型怎么从 14 模块长到 36 单元、
> 产量怎么从 9850 t/a 爬到 10221 t/a。
> [INDEX.md](./INDEX.md) 里有完整的迭代叙事、按任务的分组、以及「最值得先看的 12 个」。

## 命名约定（快速定位）

| 前缀 | 含义 | 典型用途 |
|---|---|---|
| `dump_*` | 导出/探查 | 把 bkp 段、COM 字段树、模块参数导出成文本，看"里面到底有什么" |
| `chk_*` / `check_*` | 校验 | 核对参数是否落库、物料是否平衡、结果是否与预期一致 |
| `cmp_*` | 对比 | 两个 bkp / 两组结果的逐项差异 |
| `diag_*` | 诊断 | 针对某个异常（不收敛、温度异常、组分缺失）做定向排查 |
| `test_*` | 受控实验 | 一次只改一个变量，验证某个假设（如"写 NPHASE 会不会消警告"） |
| `fix_*` / `apply_*` | 施加变更 | 把确定的修改写回模型 |
| `gen_*` | 生成 | 由计算结果生成 Excel / Word / 图表 |
| `collect_*` | 汇总 | 把散落在多处的数据收集成一张表 |
| `parse_*` | 解析 | 解析 Aspen 报告文本/TSV 为结构化数据 |
| `probe_*` / `explore_*` | 探路 | 不确定 API/字段时的试探脚本 |
| **`run_*`** | **主线** | **模型迭代的每一步（编号递增 = 项目在推进），见 [INDEX.md](./INDEX.md)** |

## 使用提醒

1. **环境不同**：脚本里有大量硬编码的绝对路径（已替换为占位符，对照表见
   [`../来源与许可.md`](../来源与许可.md)），移植时需先替换。
2. **多为一次性工具**：写的时候以"这一轮排查够用"为目标，缺少参数化与错误处理。
   若要长期复用，建议按功能归类、补 docstring、抽出公共模块。
3. **COM 脚本耗时**：凡 `win32com` 打开模型的脚本，单次运行 **3–10 分钟**，请后台执行。
4. **两个 Python 环境**：
   - COM 脚本 → 装了 `pywin32` 的那个（本机为 `D:\<化工运行时>\python-env`，CPython 3.14）
   - 表格/文档处理 → 装了 `openpyxl` / `python-docx` 的那个
5. **有些脚本是「同一次改动的多次尝试」**：`fix_all_v2`~`v6`、`run_v10`~`v12`、`run_p1`~`p6`
   都属于这类。读的时候看**最后一个成功的**，前面的看思路即可。

## 一条最重要的经验

> **改完 `.bkp` 必须回读确认。**

因为文本替换**返 0 也不报错** —— 字段名写错（`BASIS_RR` vs `BASIS-RR`）会**静默失效**，
你以为改了，其实什么都没发生。本目录里大量的 `chk_*` / `check_*` / `verify*` 脚本，
就是为这件事存在的。
