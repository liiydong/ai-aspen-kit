## 这个目录里的经验，浓缩成 10 条

如果只给你 10 句话，是这 10 句：

1. **Aspen 有两个环境**：`物性`(Properties) 里 F5 是算参数，`模拟`(Simulation) 里 F5 是跑流程。
   让程序在"模拟"环境做参数估算，会陷入「运行要求先有参数、参数要靠运行产生」的死循环。
2. **只用 `.bkp` 交付**。`.apwz` 是 ZIP，里面的 `.bkp.backup` 是**降级备份**——缺 `DATABANKS`，且 `RUN-CLASS` 可能退回 `PROP`。
3. **健康模型的判据**：`\Data` 下有 **25 个子节点**，且含 `Streams` / `Blocks` / `Flowsheet`。
   只有 8 个 → `RUN-CLASS = PROP` 了，流程图根本没加载。
4. **树路径里 `Binary Interaction` 和 `Molecular Structure` 带空格**。写成 `Binary` 会静默返回 `None`。
5. **bkp 文本注入的记录分隔符是单个 `\`**。参考文件里看到的 `\ \` 是行末换行符，照抄成一行会让**整段不解析**。
6. **每约 76 字符会折行**，会把 `BLOCK BLKID = "X"`、`? STREAM MATERIAL` 拆开 → 定位必须用容忍换行的正则，`str.find` 会失败。
7. **COM 不能建模块、不能加组分、不能写分子结构、不能写流股的 TEMP/PRES**。
   能建流股、能写模块参数、能写组分流量、能运行取数。**其余全靠文本注入。**
8. **`Run2()` 是异步的**：必须 `pythoncom.PumpWaitingMessages()` + 轮询 `IsRunning`，否则拿到全 `None`。
9. **判断参数有没有生效，看保存后文件里的 `UVAL` 条数**，不是 COM 的 `Output\CID1` —— 那个永远是 0 行，连出厂示例也是。
10. **`.bkp` 不保存计算结果**：必须"打开 → 运行 → 同一进程内读取/导出"。

## ⚠️ 给接手者的重要提醒：上游包里有一套 MCP，本项目当时没用

上游工具包（`chemical-engineering-skills`）的 `vendor/aspen-mcp-toolkit/` 里，
有一套**已经解决了本项目多个难题的 Aspen MCP 服务器**（70 个工具 + 70 种模块的参数文档）。

**本项目没有用它** —— 下面的全部经验是**手写 COM 脚本**一点点试出来的。
如果你要接手或复现，**建议先看那套 MCP**，可能省你几天：

| 本项目踩过的坑 / 得出的结论 | MCP 工具包里已有的做法 |
|---|---|
| 组分 `Elements.Add` 报 `Aspen.Variable Access` → **结论「组分只能由用户在 GUI 输入」** | ✅ 它不用 `Elements.Add`，而是在 `Components → Specifications → Input → TYPE` 表上 `InsertRow` + `SetLabel(0,0)` —— **绕过去了** |
| `Blocks.Elements.Add(...)` 8 种签名全报 `Invalid Block/Model/Library Specification` → **结论「模块无法创建」** | ✅ 它提供 `add_block(name, type)` |
| 流股 `TEMP`/`PRES` 报 `AE_UNDERSPEC`（本项目到第 3 天才攻破要走 `MIXED` 子节点） | ✅ 它的 `set_stream_param` **一开始就知道**要去 `MIXED` 写 |
| 运行前必须先 `Reinit()`（本项目踩过才明白） | ✅ 它直接提供 `reinit_and_run()` 一步到位 |
| —（本项目日志里**没有**这条） | ✅ **删除顺序铁律：先删块、再清物流。绝不能反过来** —— 反过来会让 COM 服务器异常且**无法恢复**（原理：Mixer 这类块要求至少有一条连接才能存在） |
| COM 报错后不知道还能不能继续 | ✅ 它有**错误分级表**（哪些可重试、哪些必须 `close_file` → `open_file` 恢复） |

**但也别全盘否定本包的经验** —— 上面那些结论是在**没有 MCP** 的前提下独立得出的，
而且 `.bkp` 文本注入这一层（本包的主战场）**MCP 完全没有覆盖**。两者是互补的：

| | 擅长 |
|---|---|
| **MCP 工具包** | 已有模型的参数调优、批量运行、读结果、加组分/建模块 |
| **本包经验** | `.bkp` 文件级手术、物性方法与选项集注入、反应网络注入、报告解析核对 |

> 本项目当时的「合法搭建流程」是：**用户在 GUI 里拖骨架（约 15 分钟）→ 脚本接管其余全部**。
> 而 MCP 声称可以更大程度地自动化拓扑搭建。

**MCP 的获取方式**：在上游工具包的发行页下载完整离线包，见
[`../README.md`](../README.md)。本仓库**不转载**它（上游未声明许可证）。
